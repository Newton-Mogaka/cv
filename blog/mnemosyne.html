Mnemosyne is the goddess of memory in Greek mythology, the mother of the nine Muses, the keeper of all that is known and remembered. It's also the name of a memory system I built for AI agents — one that scores what to remember using a graph neural network instead of similarity search alone.

Inspiration

From the competition brief, I was given a list of problems to choose from. I read through all of them. Persistent memory was the one I kept coming back to — not because it looked easy, but because it felt like the most honest problem on the list. Every other capability you might build into an agent runs into the same wall eventually: the agent doesn't remember you. It doesn't know what you told it last week, what you prefer, what you're working on, or what you already tried. You rebuild context from scratch every session, and the agent stays a stranger no matter how many times you talk to it.

I wanted to build something that solved that at a level deeper than storing a transcript and replaying it — a system where memory has structure, weight, and intelligence, where the agent doesn't just recall what you said, but understands what matters, what's related, and what can safely be forgotten.

The architectural idea came from an unexpected direction. I'd spent a lot of time watching how platforms like Twitter build personalized timelines from a user's very first interaction, and what struck me was that the recommendation engine isn't just matching content to stated preferences — it's learning a graph of relationships between topics, accounts, and engagement patterns. The platform is reasoning over a graph of behavior, not a flat list of likes.

That observation turned into a direct question: if an agent's memories are nodes, and semantic similarity creates edges between them, could a graph neural network learn which memories actually matter for a given query better than vector search alone? Mnemosyne was built to test that hypothesis.

What I Learned

Persistent memory in production is a largely unsolved problem. Before writing a line of code I researched how memory is actually handled in AI applications today. Most systems either append the full conversation history to every prompt — which hits context limits fast and buries what matters in noise — or keep a rolling summary that loses specificity over time. Neither gives an agent genuine long-term memory.

Not all memories are the same kind of thing. A behavioral rule ("always give concise answers"), a stable fact ("the user is a software engineer"), a stated preference ("the user prefers dark mode"), and a past episode ("the user asked about async IO last Tuesday") have different lifespans, different importance, and different roles in how an agent should reason. Building that taxonomy into the schema from day one, rather than treating all memories as undifferentiated text, was crucial for the GNN to learn meaningful patterns.

System Architecture

Mnemosyne consists of three core components working in concert:

  1. Memory Encoder: Each interaction turn gets encoded into a memory node with attributes:
    • Content embedding (SBERT for semantic richness)
    • Metadata (timestamp, speaker, topic tags)
    • Memory type classification (fact, preference, procedure, episodic)
  2. Memory Graph: Nodes are connected via learned edges representing:
    • Temporal proximity (when memories occurred)
    • Semantic similarity (content embedding distance)
    • Associative links (entity co-occurrence, pronoun resolution)
    • Importance weights (based on user feedback signals)
  3. GNN Scorer: A GraphSAGE-based network that, given a query context, propagates activation through the graph to compute a relevance score for each memory node. The architecture:
    • 2-layer GraphSAGE with mean pooling
    • Node features: [content embedding, memory type one-hot, time decay feature]
    • Edge features: [temporal distance, semantic similarity, association strength]
    • Output: relevance score used to rank memories for injection into LLM context

The Identity Bug That Quietly Broke Everything

Early versions showed promising results in isolation, but when integrated with the LLM agent, performance degraded mysteriously. The agent would forget basic user facts after just a few turns. After days of debugging, I traced it to a subtle issue in how memory nodes were being updated:

  • When the LLM generated a response, that response was being encoded as a new memory node
  • However, the system wasn't distinguishing between user-provided facts and agent-generated content
  • Over time, the graph became cluttered with low-value "memories" that were just the agent talking to itself
  • The GNN scorer, trying to be helpful, started prioritizing these self-generated memories because they were highly similar to recent context

The fix was simple in retrospect but took too long to spot: adding a source attribute to each memory node (USER, AGENT, SYSTEM) and modifying the GNN to deprioritize AGENT-source memories unless they contained verified information. This dramatically improved long-term coherence.

Evaluation and Results

I tested Mnemosyne against three baselines in a simulated 50-turn conversation:

  • Full History: Append all turns to prompt (context limit exceeded at turn 12)
  • Rolling Summary: GPT-4 summary of last 5 turns (lost specific details after 20 turns)
  • Vector Search: Top-k similar memories via cosine similarity (better, but missed relational connections)
  • Mnemosyne (GNN): Maintained 89% fact retention at turn 50 vs 45% for vector search

More importantly, in ablation studies, removing the GNN and falling back to similarity search dropped performance by 32% — proving that the graph structure was doing real work beyond simple embeddings.

What I'd Do Differently

Building this taught me humility about memory systems. If I were to rebuild Mnemosyne today:

  1. Start with a smaller, cleaner graph: I tried to capture too many relationship types early on. A phased approach — temporal first, then semantic, then associative — would have been more stable.
  2. Implement memory consolidation: Human memory isn't just storage; we actively reorganize during sleep. A nightly process to strengthen important connections and prune noise would improve long-term retention.
  3. Add uncertainty awareness: The GNN gives relevance scores, but we should also estimate confidence in those scores. Low-confidence memories could be flagged for user verification rather than silently used.

Despite its flaws, Mnemosyne worked well enough to win awards in the hackathon series where I built it. More importantly, it changed how I think about AI memory: not as a database to query, but as a dynamic knowledge graph that evolves with each interaction.

The full implementation is open source on GitHub. I hope it inspires others to look beyond vector databases when building AI systems that need to remember what matters — not just what was said.
